# Выбор оружия в бою

- **Статус:** принято и реализовано для Quick Demo
- **Обновлено:** 2026-07-28
- **Источник задачи:** Linear `AND-6`

## 1. Задача взаимодействия

Во время прицеливания игрок должен решать четыре разных сценария без длинного
последовательного перебора 33 позиций:

1. повторить уже выбранное оружие;
2. быстро найти знакомое оружие;
3. исследовать незнакомую позицию по механической роли;
4. понять текущий боезапас и причину недоступности.

Базовый снаряд остаётся первым и всегда доступным. Selector меняет только
выбранный `weaponId`: inventory, simulation, экономика и Fire не меняются.

## 2. Рассмотренные модели

### Вариант A: постоянная лента с фильтрами

Лента остаётся частью нижней панели, но получает категории и показывает только
одну группу за раз.

Desktop:

```text
┌ angle ┐  [Все][Удар][Грунт−][Грунт+][Энергия]  ┌ power / FIRE ┐
│       │  [weapon][weapon][weapon][weapon]       │              │
└───────┘                                         └──────────────┘
```

Телефон landscape:

```text
┌ angle ┐ [group ▾] [weapon][weapon][weapon] ┌ power / FIRE ┐
└───────┘      горизонтальная прокрутка       └──────────────┘
```

Плюсы: нет отдельного открытия, выбранное оружие остаётся рядом с прицелом.
Минусы: фильтры и карточки постоянно отнимают высоту у поля; на телефоне всё
ещё нужна горизонтальная прокрутка; исследование 33 позиций конфликтует с
быстрым ритмом прицеливания.

### Вариант B: current-weapon control и modal Arsenal Deck

В закрытом состоянии нижняя панель показывает одну крупную кнопку текущего
оружия. Она открывает modal selector с категориями и прокручиваемой сеткой.

Desktop, закрыто:

```text
┌ angle ┐  ┌ Star Shell · Удар · ∞ базовый  [Открыть арсенал] ┐  ┌ power / FIRE ┐
└───────┘  └───────────────────────────────────────────────────┘  └──────────────┘
```

Desktop, открыто:

```text
┌──────────────────────────── Arsenal Deck · 33 ──────────────────────────── [×] ┐
│ [Все 33] [Удар] [Разрушить] [Создать грунт] [Пристрелка] [Энергия]            │
│ [✓ selected] [weapon] [weapon] [Нет заряда] [weapon] ...                       │
│ [weapon]     [weapon] [weapon] [weapon]     [weapon] ...                       │
└─────────────────────────────────────────────────────────────────────────────────┘
```

Телефон landscape, открыто:

```text
┌──────────── нижний modal sheet; поле затемнено и Fire недоступен ────────────┐
│ Арсенал 33                                                        [Закрыть] │
│ < горизонтально прокручиваемые категории >                                  │
│ [weapon + ammo] [weapon + ammo] [weapon + ammo]  вертикальная прокрутка      │
└───────────────────────────────────────────────────────────────────────────────┘
```

Плюсы: поле и Fire не конкурируют с каталогом; текущее оружие читается всегда;
сетка использует ширину desktop и телефона; modal semantics блокирует случайный
Fire и даёт focus trap. Минус: для смены оружия требуется сначала открыть
Arsenal Deck.

## 3. Принятое решение

Принят вариант B. Native modal `dialog` даёт отдельный безопасный режим выбора:
пока Arsenal Deck открыт, нижние controls и Fire недоступны для pointer и
keyboard focus.

### Закрытое состояние

- Кнопка показывает icon, публичное название, механическую категорию и ammo.
- Для бесконечного baseline явно написано `∞ базовый`.
- `Q/E` сохраняет быстрый цикл доступных позиций без открытия selector.
- Enter/Space или pointer/tap по кнопке открывают Arsenal Deck.

### Открытое состояние

- Категории: все 33, тяжёлое, удар, разрушение, создание грунта, пристрелка и
  энергия. Spotlight «Тяжёлое» повторно собирает шесть nuclear/cluster
  позиций, не создавая новых catalog items.
- В сетке остаются все позиции выбранной категории, включая depleted.
- Selected помечается текстом `Выбрано`; depleted — текстом `Нет заряда` и
  disabled-состоянием, а не только цветом.
- Базовый снаряд идёт первым и помечается `Базовый`.
- Карточка показывает собственное публичное название, короткую механическую
  подпись и ammo без зависимости от hover. Для тяжёлых позиций подпись явно
  сообщает «малый/большой ядерный», `×3`, раскрытие в апогее `×5`, chain
  `10–14` или тяжёлый каскад `×9`.
- Заголовок постоянно сообщает «33 оружия» и правило ammo текущего режима; на
  коротком landscape viewport остаётся видимой подсказка листать каталог вниз.
- Межраундовый магазин повторяет spotlight «Тяжёлое», чтобы те же шесть
  позиций не приходилось заново искать внутри общего списка покупок.

### Keyboard и focus

- При открытии focus переходит на выбранную карточку.
- `←/↑` и `→/↓` перемещают focus к предыдущей и следующей видимой карточке;
  `Home/End` переходят к первой и последней.
- Enter/Space выбирают доступную позицию и закрывают selector.
- Escape закрывает selector без смены оружия.
- После выбора или закрытия focus возвращается на current-weapon control.
- После возврата focus стрелки сразу принадлежат прицеливанию без
  дополнительного click; Enter/Space остаются нативным способом снова открыть
  selector.
- Modal focus trap не позволяет случайно перейти к Fire.

### Pointer и touch

- Один click/tap открывает selector, второй выбирает позицию.
- Основные controls и карточки имеют минимум `44×44 CSS px`.
- На коротком landscape viewport Arsenal Deck занимает доступную высоту с
  учётом safe-area; категории прокручиваются горизонтально, каталог —
  вертикально.
- При переходе в portrait открытый selector закрывается, чтобы native dialog
  не перекрывал обязательную подсказку о повороте устройства.
- Backdrop закрывает прицеливание и Fire до явного выбора или закрытия.

## 4. Состояния и границы

- `selected`: текстовый badge плюс border/фон с weapon accent.
- `focus`: контрастный outline, независимый от accent.
- `hover`: дополнительный подъём/свечение только как desktop enhancement.
- `depleted`: disabled, сниженный контраст и текст `Нет заряда`.
- `baseline`: отдельный badge `Базовый`; никогда не depleted.
- В Infinite Arsenal каждая позиция получает `∞`, остаётся selectable и не
  использует depleted styling; selector не подменяет inventory большим
  фиктивным числом.
- Фильтр и open/closed state являются presentation-state и не попадают в
  domain или replay.
- При смене активного игрока selector закрывается, а presentation-фильтр
  сбрасывается на `Все 33`; выбранное оружие, угол, сила и inventory
  восстанавливаются из player-owned tank state.

## 5. Проверка

Автоматика должна покрывать:

- полный каталог и состав категорий;
- точный состав spotlight «Тяжёлое» и подписи шести сложных payload;
- последовательную keyboard-навигацию и границы `Home/End`;
- отсутствие depleted weapon среди выбираемых;
- сохранение `Q/E` cycle;
- focus entry/return, Escape и немедленный возврат стрелок игре — DOM
  regression и browser smoke.

Desktop browser smoke проверяет выбор, повторное открытие, focus, Escape,
depleted и отсутствие случайного Fire. Физический телефон в landscape должен
подтвердить реальные размеры touch-targets, прокрутку, safe-area и отсутствие
конфликта с системными/browser gestures; эмуляция viewport не заменяет этот
результат.
